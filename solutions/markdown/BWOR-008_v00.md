### OR Problem Analysis: Minimum Ship Deployment

#### 1. Decision Variables

To determine the minimum number of ships, we model this as a **Circulation Problem** (or Network Flow Problem) on a directed graph where nodes represent events (arrival/departure at specific cities for specific routes) and arcs represent the movement of ships (sailing or waiting).

Let:
*   $R$ be the set of routes, $R = \{1, 2, 3, 4\}$.
*   For each route $r \in R$, let $d_r$ be the destination city and $o_r$ be the origin city.
    *   Route 1: $E \to D$, sailings $n_1=3$.
    *   Route 2: $B \to C$, sailings $n_2=2$.
    *   Route 3: $A \to F$, sailings $n_3=1$.
    *   Route 4: $D \to B$, sailings $n_4=1$.
*   Let $N$ be the set of all "nodes" in the ship movement network. A node $(r, k)$ represents the completion of the $k$-th sailing of route $r$ (i.e., the ship is at destination $d_r$ after finishing service).
    *   Specifically, for each route $r$, there are $n_r$ such nodes.
*   Let $x_{ij}$ be a decision variable representing the number of ships moving from node $i$ to node $j$ in the network.
    *   $x_{ij} \ge 0$ and integer.
    *   The set of possible arcs $A$ includes:
        1.  **Sailing Arcs**: From the completion of route $r$ at destination $d_r$ to the start of route $s$ at origin $o_s$.
        2.  **Source/Sink Arcs**: To handle the initialization (new ships entering the system) and finalization (ships leaving the system or returning to depot), though in a cyclic minimum fleet problem, we often balance flow by adding a super-source and super-sink or ensuring circulation balance.

A more standard and direct formulation for the **minimum fleet size** involves calculating the **maximum cumulative deficit** or solving a **minimum flow circulation** problem.

Let us define the decision variables based on the **Ship Assignment**:
Let $y_{r, k \to s, m}$ be a binary variable (or non-negative integer) indicating if a ship finishes the $k$-th sailing of route $r$ and is assigned to perform the $m$-th sailing of route $s$.

However, the most rigorous OR formulation for "Minimum Number of Vehicles" given a set of trips is a **Minimum Cost Circulation Problem** or simply finding the **maximum flow** in a time-expanded network where the cost is 1 for "new ship entry" arcs and 0 for "reuse" arcs.

Let's refine the variables for a standard Network Flow formulation:
*   **Nodes**:
    *   $S$: Super Source.
    *   $T$: Super Sink.
    *   For each route $r$ and each sailing instance $j=1 \dots n_r$, create a **Departure Node** $D_{r,j}$ and an **Arrival Node** $A_{r,j}$.
*   **Decision Variables**:
    *   $f_{uv}$: The flow (number of ships) on arc $(u, v)$ in the constructed network.

#### 2. Objective Function

**Minimize** the total number of ships deployed.

In the network flow formulation, this is equivalent to **Minimizing the total flow entering the system from the Super Source** (representing new ships added to the fleet).

$$ \text{Minimize } Z = \sum_{v} f_{S, v} $$

Where $f_{S, v}$ is the flow from the Super Source $S$ to any node $v$. (Note: In a balanced circulation model, this is equivalent to minimizing the number of "cycles" or "paths" initiated from the source).

*Alternative Interpretation*: If we view this as finding the minimum $K$ such that a feasible circulation exists with capacity $K$ on the "return to depot" arcs, the objective is $\min K$.

#### 3. Operational Constraints

The constraints ensure that every required sailing is covered exactly once and that ship movements are physically possible (time feasibility).

**A. Flow Conservation Constraints**
For every intermediate node (Arrival or Departure nodes) in the network, the inflow must equal the outflow.
$$ \sum_{u} f_{u, v} - \sum_{w} f_{v, w} = 0 \quad \forall v \in \{ \text{All Arrival and Departure Nodes} \} $$

**B. Sailing Requirement Constraints (Coverage)**
Each specific sailing instance must be performed by exactly one ship. This is modeled by forcing a flow of 1 through the "service arc" for each sailing.
For each route $r$ and sailing instance $j=1 \dots n_r$:
$$ f_{D_{r,j}, A_{r,j}} = 1 $$
*(Where the arc from $D_{r,j}$ to $A_{r,j}$ represents the actual sailing of route $r$)*.
*Note: The capacity of this arc is 1, and the lower bound is 1.*

**C. Time Feasibility Constraints (Arc Existence)**
An arc can only exist from an Arrival Node $A_{r, k}$ (end of route $r$, sailing $k$) to a Departure Node $D_{s, m}$ (start of route $s$, sailing $m$) if the ship can physically make it in time.

Let $t_{r, k}^{end}$ be the completion time of the $k$-th sailing of route $r$.
Let $t_{s, m}^{start}$ be the start time of the $m$-th sailing of route $s$.

The ship can move from route $r$ (sailing $k$) to route $s$ (sailing $m$) if and only if:
$$ t_{r, k}^{end} + \text{LoadingTime} + \text{SailingTime}(d_r, o_s) \le t_{s, m}^{start} $$

If this condition holds, the arc $(A_{r, k}, D_{s, m})$ exists in the network with infinite capacity (or capacity $\ge 1$) and cost 0 (for reuse).
If the condition does not hold, the arc does not exist (or capacity 0).

**D. Super Source and Super Sink Connections**
*   **From Super Source $S$**: Arcs from $S$ to every Departure Node $D_{r, j}$ exist. These represent adding a new ship to the fleet to start that specific sailing. The cost of these arcs is 1 (or they are the variables in the objective function).
*   **To Super Sink $T$**: Arcs from every Arrival Node $A_{r, j}$ to $T$ exist. These represent the ship finishing its last task (or returning to the depot). The flow into $T$ must equal the flow out of $S$ (Total Fleet Size).
    $$ \sum_{v} f_{v, T} = \sum_{v} f_{S, v} $$

**E. Integer Constraints**
$$ f_{uv} \in \mathbb{Z}_{\ge 0} \quad \forall (u, v) \in \text{Arcs} $$

### Summary of the Model Structure

1.  **Network Construction**:
    *   Create a node for each "Start" and "End" of each specific sailing (e.g., Start of Route 1 Sailing 1, End of Route 1 Sailing 1).
    *   Connect "End of Route $r$" to "Start of Route $s$" if the ship can physically travel from $d_r$ to $o_s$ in the available time between the end of $r$ and start of $s$, accounting for the 1-day loading/unloading time.
    *   Connect Super Source to all "Start" nodes.
    *   Connect all "End" nodes to Super Sink.

2.  **Objective**:
    *   Minimize the total flow from the Super Source (which equals the number of ships).

3.  **Key Parameters for Calculation**:
    *   **Sailing Duration**:
        *   Route 1 (E->D): 17 days.
        *   Route 2 (B->C): 3 days.
        *   Route 3 (A->F): 7 days.
        *   Route 4 (D->B): 13 days.
    *   **Service Time**: 1 day (loading/unloading).
    *   **Total Turnaround Time per Route**:
        *   $T_1 = 17 + 1 = 18$ days.
        *   $T_2 = 3 + 1 = 4$ days.
        *   $T_3 = 7 + 1 = 8$ days.
        *   $T_4 = 13 + 1 = 14$ days.

    *   **Frequency**:
        *   Route 1: Every 1/3 day (3 times a day).
        *   Route 2: Every 1/2 day (2 times a day).
        *   Route 3: Every 1 day (1 time a day).
        *   Route 4: Every 1 day (1 time a day).

    *   **Feasibility Check Example**:
        *   Can a ship do Route 3 (A->F) then Route 2 (B->C)?
        *   Finish R3 at F. Time needed to get to B: Sailing F->B is 8 days.
        *   Total time available vs required: The ship finishes R3, needs 1 day to unload, then sails 8 days to B, then needs 1 day to load for R2. Total idle/travel time = $1 + 8 + 1 = 10$ days.
        *   Since Route 2 happens every 0.5 days, the ship must arrive at B *at least* 10 days before the next R2 departure. This is generally feasible unless the timing is extremely tight, but since we are minimizing ships, we look for the *tightest* link. The bottleneck is usually the route with the longest duration relative to its frequency.

    *   **Rough Estimate**:
        *   Route 1 requires 3 ships if it were isolated ($3 \times 18$ days coverage).
        *   Route 2 requires 2 ships ($2 \times 4$ days coverage).
        *   Route 3 requires 1 ship.
        *   Route 4 requires 1 ship.
        *   Total isolated = 7 ships.
        *   Sharing is possible if a ship finishes one route and has enough time to get to the next. Given the long sailing times (e.g., 17 days), a ship on Route 1 is occupied for 18 days. During those 18 days, Route 1 needs 54 sailings. One ship can only do 1. So Route 1 *alone* needs at least 3 ships just to keep up with its own frequency if no other route helps. Actually, since it sails 3 times a day, it needs 3 ships dedicated to it if no other ship can take over. Can a ship from Route 4 (D->B, 14 days) take over Route 1 (E->D)?
        *   Finish R4 at B. Need to get to E. Sailing B->E is 8 days. Total time $1(\text{unload}) + 8(\text{sail}) + 1(\text{load}) = 10$ days.
        *   If a ship finishes R4, it takes 10 days to be ready for R1. Since R1 is frequent, this is likely feasible.
        *   The model above will rigorously determine the exact integer minimum.
