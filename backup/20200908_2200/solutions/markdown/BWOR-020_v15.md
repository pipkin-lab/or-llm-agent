5.  **Conflict B-D**: A truck cannot serve both B and D.

6.  **Non-negativity/Integrality**:
    $z_{i,j} \in \{0,1\}, \quad \forall i \in I, j \in J$
    $y_j \in \{0,1\}, \quad \forall j \in J$

This model is a standard 0-1 Integer Programming model.

One detail: **Can a truck be used if it carries 0 customers?**
The objective minimizes cost, so it will never use a truck if it doesn't have to.
Constraint 2 allows $y_j=1$ even if sum $z=0$, but the objective will push $y_j=0$ in that case.
Constraint 3 ensures if $z=1$, $y=1$.

Is there any ambiguity about "Set Covering"?
Sometimes Set Covering allows elements to be covered by *multiple* sets (minimizing cost). Here, "assign... to the trucks" and "each used only once" strongly implies a partition (each customer exactly once). If it were pure Set Covering (overlap allowed), the constraint would be $\sum_j z_{i,j} \ge 1$. However, physically, you don't deliver the same box twice. You deliver it once.
