# Transshipment Transportation Problem

## Model Type: LP (Linear Programming)

All flows are continuous (tons of goods), and all constraints/objective are linear.

---

## 1. Index Sets & Parameters

**Sets:**
- $S = \{X, Y\}$: Source locations
- $D = \{A, B, C\}$: Destination locations
- $N = S \cup D = \{X, Y, A, B, C\}$: All nodes (sources can also act as transshipment points, and destinations can also act as transshipment points)
- $A_{od}$: Arcs where transshipment/direct shipping is possible. Based on the tables provided:
  - Table 3-23 gives distances between sources: $d_{XY}=12$, $d_{YX}=10$
  - Table 3-24 gives distances from sources to destinations:
    - $d_{XA}=10, d_{XB}=14, d_{XC}=12$
    - $d_{YA}=15, d_{YB}=12, d_{YC}=18$
  - Table 3-25 gives distances between destinations:
    - $d_{AB}=14, d_{AC}=11$
    - $d_{BA}=10, d_{BC}=4$
    - $d_{CA}=8, d_{CB}=12$
  - Self-loops: $d_{nn}=0$ for all $n \in N$

**Parameters:**
- Supply at sources (tons):
  - $s_X = 70$
  - $s_Y = 55$
- Demand at destinations (tons):
  - $d_A = 35$
  - $d_B = 40$
  - $d_C = 50$
- Total supply = 70 + 55 = 125 tons
- Total demand = 35 + 40 + 50 = 125 tons
- **Supply = Demand** → balanced problem, all balance constraints are equalities.

**Distance matrix (km), defined for all arcs $o \to o'$ with $o \neq o'$:**

| From \ To | X    | Y    | A    | B    | C    |
|-----------|------|------|------|------|------|
| **X**     | 0    | 12   | 10   | 14   | 12   |
| **Y**     | 10   | 0    | 15   | 12   | 18   |
| **A**     | [NP] | [NP] | 0    | 14   | 11   |

> **Note on [NP] (Not Provided):** Tables 3-24 and 3-25 do not provide distances from destinations A, B, C back to sources X, Y. In a transshipment network, goods could theoretically flow A→X, B→Y, etc. However, since X and Y are pure sources (net supply only) and A, B, C are pure destinations (net demand only), and the problem structure (Tables 3-23 for source-source, 3-24 for source-dest, 3-25 for dest-dest) implies that transshipment occurs only in the "forward" direction (source→source, source→dest, dest→dest), we restrict arcs to those explicitly given. No arc exists from a destination back to a source.

## 4. Operational Constraints

### Flow Balance Constraints (one per node)

Since total supply (125) equals total demand (125), all balance constraints are **equalities**.

**Node X (net supply = +70):**
$$x_{XY} + x_{XA} + x_{XB} + x_{XC} - x_{YX} = 70$$

**Node Y (net supply = +55):**
$$x_{YA} + x_{YB} + x_{YC} - x_{XY} = 55$$

**Node A (net demand = -35):**
$$x_{XA} + x_{YA} + x_{BA} + x_{CA} - x_{AB} - x_{AC} = 35$$

**Node B (net demand = -40):**
$$x_{XB} + x_{YB} + x_{AB} + x_{CB} - x_{BA} - x_{BC} = 40$$

**Node C (net demand = -50):**
$$x_{XC} + x_{YC} + x_{AC} + x_{BC} - x_{CA} - x_{CB} = 50$$

### Non-negativity:
$$x_{ij} \geq 0 \quad \forall (i,j) \in E$$

## 5. Feasibility Sanity Check

- **Total supply** = 70 + 55 = 125 tons
- **Total demand** = 35 + 40 + 50 = 125 tons
- **Balanced**: ✓
- **Network connectivity**: Every destination is reachable from at least one source via direct or transshipment arcs. E.g., A can be reached from X, Y, B, C. B from X, Y, A, C. C from X, Y, A, B. ✓
- **No artificial infeasibility**: The constraint system is a standard balanced transshipment problem with a connected directed graph, so a feasible solution exists.

### Magnitude sanity check (greedy / direct-only solution):
If we ship directly only (no transshipment), a feasible assignment is, e.g.:
- X→A: 10, X→B: 14, X→C: 12, X→Y: 34 (to help Y)
- Y→A: 25, Y→B: 26, Y→C: 38 (after receiving 34 from X, Y has 89 total)
This is just one feasible point. The objective for direct-only shipping would be on the order of $100 \times 10 = 1000$ km. With transshipment, the optimum will be ≤ this. The answer should be in the range of several hundred to ~1000 km, which is consistent with the problem's scale. ✓
